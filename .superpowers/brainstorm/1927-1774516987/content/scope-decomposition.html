This is a big scope — let's decompose into phases

Each phase is an independent spec → plan → implementation cycle. Which phase should we build first?

A

Phase 1: Enhanced Materials + Real Footprints

Upgrade the current viewer with PBR materials (glass, concrete, metal), proper roof geometry, and integrate the cadastral footprint API to replace estimated rectangles with real building shapes. This is the highest visual impact per effort.

  • Cadastral API integration (지적도 footprint polygons)
  • Extruded polygon geometry instead of boxes
  • PBR materials per structure/use type
  • Gable/flat/hip roof generation
  • Window grid texture based on floor area
B

Phase 2: IFC/glTF Upload + Model Viewer

Add file upload (IFC via web-ifc, glTF via Three.js loader). When a user has a real architectural model, it replaces the parametric one. The mass model becomes the fallback for buildings without uploaded models.

  • Drag-and-drop file upload UI
  • IFC parser (web-ifc) → Three.js scene
  • glTF/GLB loader
  • Model storage (localStorage or IndexedDB per building PK)
C

Phase 3: Energy Data Integration

Integrate 건축물 에너지효율등급 API data. Overlay energy performance on the 3D model — heat maps by floor, insulation ratings, HVAC zones. This is where it becomes an actual energy management tool.

  • Energy performance API integration
  • Floor-level heat map overlays
  • Insulation/HVAC data panels
  • Energy consumption visualization

I recommend A first — real footprints + better materials is the biggest visual leap, and it sets the geometric foundation everything else builds on.
