What level of architectural realism are we targeting?

Remember: we have building metadata (height, floors, areas, structure type, use type) but no actual geometry data — no footprint shapes, no facade details, no window/door counts. Each level adds visual detail through procedural generation.

A

Enhanced Mass Model

Keep the box-per-floor approach but add: beveled edges, glass/concrete materials, window grid textures, proper roof geometry (flat slab vs gable), and ambient occlusion shadows. Looks like an architectural massing study — clean and professional.

Pros

  • Fast to build (2-3 tasks)
  • Honest — doesn't pretend to have geometry it doesn't
  • Clean look for energy overlay dashboards

Cons

  • Still clearly "generated" — won't be confused for a real building
B

Procedural Facade Generation

Generate fake but believable facades: window grids based on floor area, entrance on ground floor, balconies for residential, curtain wall for offices, corrugated panels for factories. Building use type drives the visual style. Roof varies by type code.

Pros

  • Looks "real" from a distance
  • Use-type differentiation (apartment vs factory vs office)
  • Good base for energy zone visualization

Cons

  • More complex (5-7 tasks)
  • Procedural facades won't match actual buildings
C

Hybrid: Enhanced Mass + IFC/Model Upload

Start with Option A (polished mass model) as the default view for all buildings, but add an IFC/glTF file upload feature. If the user has a real architectural model, they can overlay it. The mass model becomes a fallback.

Pros

  • Best of both worlds — works without geometry, but supports real models
  • Most practical for energy management (real models have HVAC zones)
  • Progressive enhancement path

Cons

  • IFC parsing is complex (needs web-ifc library)
  • Larger scope (8-10 tasks)
