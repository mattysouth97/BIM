**Create src/hooks/use-onboarding-tour.ts (per D-03, D-04):**

A hook that triggers the driver.js tour on first workspace visit:

```typescript
import { useEffect } from "react";
import { useAppStore } from "@/store/app-store";
import { useHydration } from "@/hooks/use-hydration";
```

1. Read `hasSeenTour` from app-store. Read `hydrated` from useHydration().
2. In a useEffect (deps: [hydrated, hasSeenTour]):
   - If not hydrated or hasSeenTour is true, return early.
   - Dynamically import driver.js: `const { driver } = await import("driver.js")` and also import the CSS `import("driver.js/dist/driver.css")`.
   - Create a driver instance with 4 steps (per D-04):
     - Step 1: element `[data-tour="stepper"]`, title "Workflow Pipeline" / "작업 흐름", description "Navigate through 5 stages: Select Building, Assemble, Configure, Analyze, Export" / Korean equivalent.
     - Step 2: element `[data-tour="viewport"]`, title "3D Viewport" / "3D 뷰포트", description "Your building visualization. Rotate, zoom, and interact with the model here."
     - Step 3: element `[data-tour="left-dock"]`, title "Scene & Components" / "씬 & 구성요소", description "Browse the scene tree and drag components from the catalog."
     - Step 4: element `[data-tour="right-dock"]`, title "Properties" / "속성", description "Edit selected element properties. Changes update the 3D view in real time."
   - Use `useAppStore.getState().language` for Korean vs English text selection.
   - Configure driver with `showProgress: true`, `animate: true`.
   - On destroy callback (or after last step), call `useAppStore.getState().setHasSeenTour(true)`.
   - Call `driverObj.drive()` to start the tour.
   - Return cleanup: `driverObj.destroy()`.

3. Export `useOnboardingTour`.

Note: driver.js is framework-agnostic and manipulates DOM directly. The dynamic import avoids SSR issues.
