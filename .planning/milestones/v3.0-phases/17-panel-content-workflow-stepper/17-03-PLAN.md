       - `RemoveWallCommand`: constructor takes `WallSegment`. At construction time, snapshot dependent openings: `usePlanStore.getState().openings.filter(o => o.wallId === wall.id)`. execute() removes openings then wall. undo() adds wall then openings back — per UNDO_REDO.md section 8 Case 1.

       - All IDs are captured at construction time, not regenerated — per UNDO_REDO.md pitfall 5.

    2. Create `src/lib/undo/commands/component-commands.ts`:
       - `PlaceComponentCommand`: constructor takes `pk: string` and `PlacedComponent` (with instanceId already generated). execute() calls `useComponentStore.getState().placeComponent(pk, component)`. undo() calls `removeComponent(pk, component.instanceId)`.
       - `RemoveComponentCommand`: constructor takes `pk: string` and `PlacedComponent`. execute() calls removeComponent(). undo() calls placeComponent() to restore.
       - `UpdatePositionCommand`: constructor takes pk, instanceId, oldPos, newPos. execute() calls updatePosition(pk, instanceId, newPos). undo() calls updatePosition(pk, instanceId, oldPos). Implements `update(newer)`: if same pk and instanceId, updates newPos and returns true (drag coalescing).

    3. Create `src/lib/undo/commands/material-commands.ts`:
       - `OverrideMaterialCommand`: constructor takes `pk: string`, `path: string`, `oldValue: unknown`, `newValue: unknown`. execute() calls `useMaterialStore.getState().overrideProperty(pk, path, newValue)`. undo() calls `overrideProperty(pk, path, oldValue)`.
       - Implements `update(newer)`: if newer is OverrideMaterialCommand with same pk and path, update `this.newValue = newer.newValue`, return true. This coalesces slider drags into a single undo step — per UNDO_REDO.md section 7.
       - `oldValue` is captured by the caller before constructing the command (snapshot at construction time).

    All files: no React imports, no hooks. Pure TypeScript classes importing store via `getState()`.
