# Plan 01: Korean Energy APIs + Actual vs Modeled Comparison

<objective>
Create API proxy routes for Korean energy consumption and weather data, a client hook for fetching actual energy data, and update energy cards to show modeled vs actual comparison with delta indicators.
</objective>

<tasks>

<task id="1">
<title>API proxy routes for energy and weather data</title>
<read_first>
- src/app/api/bldrgst/title/route.ts
- src/lib/api-proxy.ts
- src/lib/api-client.ts
</read_first>
<action>
Create `src/app/api/energy/consumption/route.ts`:
- GET handler that proxies to data.go.kr 건물에너지정보 API
- Base URL: `https://apis.data.go.kr/1613000/BdEnergyUseService` (building energy use)
- Accept query params: mgmBldrgstPk, year
- Forward serviceKey from x-api-key header
- Return monthly electricity (kWh) and gas (MJ) consumption data
- Follow same pattern as bldrgst routes

Create `src/app/api/energy/grade/route.ts`:
- GET handler for 건축물 에너지효율등급 API
- Base URL: `https://apis.data.go.kr/1613000/BdEnergyRatingService`
- Accept: mgmBldrgstPk
- Return certified energy grade + primary energy demand

Create `src/app/api/weather/route.ts`:
- GET handler for KMA ASOS weather data
- Base URL: `https://apis.data.go.kr/1360000/AsosHourlyInfoService`
- Accept: stnId (station ID, default 108 = Seoul), startDate, endDate
- Return temperature data for degree-day calculation
- Note: this API may need a separate service key — handle gracefully if unavailable

Create `src/lib/energy-api-client.ts`:
- Export `fetchEnergyConsumption(pk: string, year?: number): Promise<{ monthly: { month: number, electricity: number, gas: number }[] } | null>`
- Export `fetchEnergyGrade(pk: string): Promise<{ grade: string, demand: number } | null>`
- Export `fetchWeatherData(year?: number): Promise<{ monthly: { month: number, avgTemp: number }[] } | null>`
- All use the same API key pattern as api-client.ts
- Return null on error (API may not have data for all buildings)
</action>
<acceptance_criteria>
- 3 API route files exist in src/app/api/energy/ and src/app/api/weather/
- Each follows the bldrgst route proxy pattern
- energy-api-client.ts exports 3 fetch functions
- Functions return typed data or null on failure
- `pnpm build` passes
</acceptance_criteria>
</task>

<read_first>

<action>
Create `src/hooks/use-actual-energy.ts`:
- Export interface `ActualEnergy`: { grade: string | null, monthlyConsumption: { month: number, electricity: number, gas: number }[] | null, totalAnnualKwh: number | null, dataAvailable: boolean }
- Export `useActualEnergy(buildingPk: string): ActualEnergy`
  - Fetch energy grade and consumption on mount
  - Cache results to avoid refetching
  - Handle missing data gracefully (many buildings won't have energy data)
  - totalAnnualKwh = sum of monthly electricity + gas converted to kWh
  - dataAvailable = true only if at least one API returned data
</action>
<acceptance_criteria>

</task>
