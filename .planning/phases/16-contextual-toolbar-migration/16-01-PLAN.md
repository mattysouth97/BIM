```typescript
import type { LucideIcon } from "lucide-react";
import type { WorkflowStage } from "./stages";

export type ToolbarItemType = "button" | "toggle" | "separator";

  id: string;
  type: ToolbarItemType;
  icon?: LucideIcon;
  labelEn: string;
  labelKo: string;
  /** Store selector path for active/pressed state, e.g. "authoring.isAuthoring" */
  activeWhen?: string;
}

export interface ToolbarGroup {

  labelEn: string;
  labelKo: string;
  items: ToolbarItem[];
}
```

Create `src/components/workspace/contextual-toolbar.tsx`.

**Per D-02:** Horizontal strip at the top of the viewport panel (inside WorkspaceShell center panel, above the Canvas). Fixed height: `h-10` (40px). Uses `flex items-center` with `gap-1` for button groups.

**Per D-03:** Mode indicator as a compact Badge in the toolbar strip showing current tool name + icon with distinct background color. The badge reads:
- drawingMode === "wall" → "Draw Wall" / PenTool icon / blue bg
- drawingMode === "opening" → "Place Opening" / DoorOpen icon / green bg
- annotationMode !== "none" → annotation mode name / appropriate icon / purple bg
- transformMode when isAuthoring → "Move"/"Rotate"/"Scale" / icon / amber bg
- Default (no active tool) → "Select" / cursor icon / neutral bg
This satisfies FLOW-02.

**Per D-07:** Toolbar items trigger actions via direct store calls (e.g., usePlanStore.getState().setDrawingMode('wall')) — no event bus.

**Component props:**

**Rendering logic:**
1. Read `stage` from `useWorkflowStore`
2. Look up `TOOLBAR_CONFIGS[stage]` for the stage-specific groups
3. Render each group with separators between groups
4. The global section (view presets, plan toggle) is always rendered on the right side

**For "assemble" stage, render special sub-panels:**
Instead of rendering complex controls (floor selector, snap settings, grid size, opening presets) as toolbar buttons, render them as small popover sub-panels that appear below the toolbar when the relevant mode is active. Specifically:
- Floor selector + grid size + snap controls appear when viewMode === "plan" (rendered as a small dropdown/popover below the toolbar, not as inline toolbar items)
- Opening preset selector appears when drawingMode === "opening" (as a popover)
- Section cut slider appears when annotationMode === "section" (as a popover below the toolbar)

These sub-panels must contain all the same controls as viewer-overlay.tsx lines 344-593 (floor buttons, grid size buttons, snap checkboxes, drawing mode buttons, opening presets, wall draw status, axis lock info, opening placement status).

**Bottom info overlays migrated to the toolbar component:**
- Building info badges (name, era, model source) — render in the toolbar left section instead of as absolute-positioned overlays
- Floor info card when a floor is selected — render as a small popover/tooltip from the toolbar or as a bottom-left absolute overlay within the viewport (keep existing position pattern)
- Instructions text (bottom-right) — keep as viewport overlay inside the component

**Use `useAppStore((s) => s.language)` for i18n**, same pattern as viewer-overlay.tsx.

All buttons use shadcn `<Button variant="ghost" size="icon" className="h-7 w-7">` for toolbar density. Active state uses `variant="default"`.
