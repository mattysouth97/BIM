# Read-only corpus browser

## Goal

Make published corpus releases inspectable through the existing dataset outlet. `/corpus` is a read-only data browser linked beside gallery/model downloads, not another diagnostic workflow.

## Tasks

1. Consume release and record APIs with abortable requests, actual coverage filter options, release selection, ID/code/era search and pagination. Handle no releases and unavailable storage separately; never substitute fixture or stale records.
2. Expose whole-release JSON, dictionary, immutable record links, dated versions, coverage/omissions, exclusions, assumption prevalence and changelog. Keep internal consistency and unvalidated building-stock accuracy in separate statements.
3. Verify API query behavior and unavailable states, Korean/English layouts at 390 and 1440 px, source/assumption visibility and no horizontal overflow. Validate a real published release on the configured integration environment after publication review.

## Ownership

UI agent owns `src/app/corpus`, `src/components/corpus`, the existing dataset-outlet link and scoped tests. Backend agent owns API/storage/publication and Phase4 owns generation. No runtime schema or generator duplication; imports from backend modules are type-only.
