Modify layer-panel.tsx to add a chevron and 4 indented sub-toggle rows under the MEP layer row.

1. **New imports** (add to existing import lines):
   - `import { useState } from "react";` (React -- for local chevron expand state)
   - `import { X, ChevronDown } from "lucide-react";` (add ChevronDown to existing X import)
   - `import { MEP_SUB_IDS, MEP_SUB_CONFIGS } from "@/lib/layers/types";` (add alongside existing LAYER_CONFIGS, ALL_LAYER_IDS imports)

2. **New store selectors** (add inside the component, after existing selectors):
   ```typescript
   const mepSubVisibility = useLayerStore((s) => s.mepSubVisibility);
   const toggleMepSub = useLayerStore((s) => s.toggleMepSub);
   ```

3. **Local expand state** (add inside component, after store selectors):
   ```typescript
   const [mepExpanded, setMepExpanded] = useState(false);
   ```
   This is UI-only transient state -- NOT persisted. Resets to collapsed on panel re-mount.

4. **Modify the MEP row rendering** inside the `ALL_LAYER_IDS.map()` loop. When `id === "mep"`, the row needs TWO changes:
   a. Add a chevron button at the END of the existing button content (after the label/description span), inside the same button:
      ```tsx
      <ChevronDown
        className={`ml-auto h-3 w-3 shrink-0 text-muted-foreground transition-transform duration-150 ${
          mepExpanded ? "" : "-rotate-90"
        }`}
        onClick={(e) => {
          e.stopPropagation();
          setMepExpanded((prev) => !prev);
        }}
      />
      ```
      The `e.stopPropagation()` is CRITICAL -- clicking the chevron must NOT trigger `toggleLayer("mep")`. The chevron only controls expand/collapse.

   b. Immediately AFTER the MEP button element (still inside the `ALL_LAYER_IDS.map()` callback, returned as a fragment or wrapper div), conditionally render the sub-toggle rows:
      ```tsx
      {id === "mep" && mepExpanded && MEP_SUB_IDS.map((subId) => {
        const subConfig = MEP_SUB_CONFIGS[subId];
        const subActive = mepSubVisibility[subId];
        return (
          <button
            key={subId}
            type="button"
            onClick={() => toggleMepSub(subId)}
            className="flex w-full items-start gap-3 rounded-md pl-8 pr-3 py-1.5 text-left text-xs transition-colors hover:bg-accent/50"
          >
            <span
              className="mt-0.5 size-2 shrink-0 rounded-full border-2 transition-colors"
              style={{
                borderColor: subConfig.color,
                backgroundColor: subActive ? subConfig.color : "transparent",
              }}
            />
            <span className={subActive ? "font-medium" : "text-muted-foreground"}>
              {isKo ? subConfig.nameKo : subConfig.name}
            </span>
          </button>
        );
      })}
      ```

   Per CONTEXT.md locked decisions on sub-toggle styling:
   - Sub-dot: `size-2` (smaller than parent `size-2.5`) per locked decision
   - Sub-row indentation: `pl-8` (deeper than parent `px-3`) -- visually subordinate
   - Sub-row text: `text-muted-foreground` when inactive, `font-medium` when active (slightly lighter than parent active text)
   - Sub-row padding: `py-1.5` (tighter than parent `py-2`)
   - No description line on sub-rows (only parent rows get the description)

   To return both the parent button and the sub-rows from the map callback, wrap in a React Fragment:
   ```tsx
   return (
     <Fragment key={id}>
       <button ...>{/* existing dot + label + chevron for mep */}</button>
       {id === "mep" && mepExpanded && MEP_SUB_IDS.map(...)}
     </Fragment>
   );
   ```
   For non-MEP rows, the existing `<button key={id}>` return is unchanged (no Fragment wrapper needed, or wrap consistently for all rows -- either approach is fine).

   Add `import { Fragment } from "react";` if using Fragment (or use `<>...</>` shorthand, but keys require Fragment).

5. **Do NOT add useHydration guard** -- the initial mepSubVisibility is all-true (matching defaults), so no SSR hydration mismatch occurs on first load. If a user has customized and persisted sub-layer states, the mismatch risk is minimal since LayerPanel is rendered client-side inside the R3F viewer context. Only add useHydration if a visible flash is observed during manual testing.
