# Plan 02: Error Boundaries + Input Validation

<objective>
Add React error boundaries around crash-prone areas (R3F Canvas, config panels, energy cards) and input validation on all config sliders to prevent impossible values.
</objective>

<tasks>

<task id="1">
<title>React error boundary component</title>
<read_first>
- src/components/viewer/building-scene.tsx
- src/app/layout.tsx
</read_first>
<action>
Create `src/components/error-boundary.tsx`:
- React 19 class component ErrorBoundary (functional components can't catch render errors)
- Props: children, fallback?: ReactNode, onError?: (error, errorInfo) => void
- State: hasError, error
- getDerivedStateFromError: set hasError = true
- componentDidCatch: log error, call onError prop
- Default fallback: card with error message, "Reload" button (window.location.reload)
- 3D-specific fallback: "3D viewer encountered an error. This may be a WebGL issue." + retry button
- Export `ErrorBoundary` and `ViewerErrorBoundary` (pre-configured for 3D)

Update `src/components/viewer/building-scene.tsx`:
- Wrap the Canvas in `<ViewerErrorBoundary>`
- Wrap ConfigPanel in `<ErrorBoundary>`
- Wrap EnergyCards in `<ErrorBoundary>`
- Wrap ComponentPalette in `<ErrorBoundary>`
- Wrap PropertiesPanel in `<ErrorBoundary>`
</action>
<acceptance_criteria>
- `src/components/error-boundary.tsx` exports `ErrorBoundary` and `ViewerErrorBoundary`
- Canvas wrapped in ViewerErrorBoundary
- ConfigPanel, EnergyCards wrapped in ErrorBoundary
- Error shows friendly fallback instead of white screen
- `pnpm build` passes
</acceptance_criteria>
</task>

<task id="2">
<title>Config panel input validation</title>
<read_first>
- src/components/viewer/config-tabs/building-tab.tsx
- src/components/viewer/config-tabs/envelope-tab.tsx
- src/components/viewer/config-tabs/systems-tab.tsx
- src/components/viewer/config-tabs/slider-row.tsx
</read_first>
<action>
Update `src/components/viewer/config-tabs/slider-row.tsx`:
- Add `validate?: (value: number) => string | null` prop
- Show validation error message below slider when validation fails
- Clamp value to min/max on blur (in case direct input exceeds bounds)
- Add aria-invalid when validation error exists

Update `src/components/viewer/config-tabs/building-tab.tsx`:
- Add validation rules:
  - Footprint width/depth: min 2m, max 100m, warn if < 4m ("Below typical minimum")
  - Floor count: min 1, max 50
  - Floor height: min 2.2m (Korean building code minimum), max 6m
  - Wall thickness: min 0.05m, max 1m
  - Window ratio: min 0%, max 80% (Korean code limit)
  - Column spacing: min 2m, max 15m
  - Column size: min 0.15m, max 1.2m

Update `src/components/viewer/config-tabs/envelope-tab.tsx`:
- Wall U-value: min 0.1, max 5.0 (warn > 2.5: "Exceeds Korean code limit for most zones")
- Window U-value: min 0.5, max 6.0
- SHGC: min 0.05, max 0.95
- WWR: min 0, max 80 (warn > 60: "Exceeds Korean code limit")

Update `src/components/viewer/config-tabs/systems-tab.tsx`:
- Heating efficiency: min 50, max 100
- Cooling COP: min 1.5, max 8.0
- LPD: min 2, max 30
- Solar area: min 0, max 10000

Update `src/components/viewer/wall-drawer.tsx`:
- Minimum wall length: 0.5m (reject shorter segments)
- Maximum wall length: 50m (warn but allow)
- Show measurement tooltip while drawing (line length in meters)
</action>
<acceptance_criteria>
- SliderRow shows validation errors when value out of range
- Building tab has validation on all sliders
- Envelope tab warns when exceeding Korean code limits
- Wall drawer rejects walls shorter than 0.5m
- Wall drawer shows length tooltip while drawing
- `pnpm build` passes
</acceptance_criteria>
</task>
