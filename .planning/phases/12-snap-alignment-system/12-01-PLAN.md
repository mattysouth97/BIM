1. Create `src/lib/plan/snap-engine.ts` with pure snap functions:

```typescript
export type SnapType = "grid" | "vertex" | "edge" | "none";

export interface SnapResult {
  type: SnapType;
  point: [number, number]; // snapped x, z
  sourceId?: string;       // wall id for vertex/edge snaps
  distance: number;        // distance from raw point to snap point
}

export interface SnapConfig {
  enabled: boolean;
  gridSnap: boolean;
  vertexSnap: boolean;
  edgeSnap: boolean;
  gridSize: number;           // meters (0.1, 0.5, 1.0)
  proximityTolerance: number; // meters, default 0.3
}
```

Functions to implement:

- `snapToGrid(x, z, gridSize)`: Round x and z to nearest gridSize multiple. Return SnapResult with type "grid".

- `snapToVertex(x, z, walls, tolerance)`: Iterate all wall start/end points. Find closest within tolerance. Return SnapResult with type "vertex" and sourceId. Return null if none within tolerance.

- `snapToEdge(x, z, walls, tolerance)`: For each wall, use projectOntoWall logic (inline, don't import -- keep snap-engine dependency-free). Find closest edge projection within tolerance. Return SnapResult with type "edge" and sourceId. Return null if none.

- `computeSnap(x, z, walls, config)`: Main entry point. If not enabled, return {type:"none", point:[x,z], distance:0}. Check vertex first (highest priority), then edge, then grid. Return the first match. Priority: vertex (if within tolerance) > edge (if within tolerance) > grid (always succeeds if gridSnap enabled) > none.

The `walls` parameter accepts `Array<{id: string; start: [number, number]; end: [number, number]}>` -- a subset of WallSegment fields so the engine stays decoupled.
