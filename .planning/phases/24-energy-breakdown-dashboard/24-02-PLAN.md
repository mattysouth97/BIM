<task type="auto">
  <name>Task 1: Wrap EnergyBreakdownChart in React.memo</name>
  <files>src/components/viewer/energy-breakdown-chart.tsx</files>
  <action>
    Add a React.memo boundary to isolate the chart from any parent re-render whose props (just `buildingPk`) did not change. This is the defense-in-depth per RESEARCH.md Layer 3 ("Component boundary"):

    "If it appears [in profiler commits during orbit], find which parent is re-rendering and apply React.memo() on EnergyBreakdownChart with default shallow comparison."

    Do this preemptively rather than waiting for a profiler failure — the cost is ~3 lines of code, the benefit is SC4 becomes a guarantee rather than a hope.

    Exact changes in src/components/viewer/energy-breakdown-chart.tsx:

    1. Add `memo` to the react import:
       - Change `import { useMemo } from "react";`
       - To `import { memo, useMemo } from "react";`

    2. Rename the implementation function and export a memo-wrapped version:
       - Change `export function EnergyBreakdownChart({ buildingPk }: EnergyBreakdownChartProps) {`
         (the top of the component body)
       - To `function EnergyBreakdownChartImpl({ buildingPk }: EnergyBreakdownChartProps) {`

       - At the BOTTOM of the file, after the component closes, add:
         ```typescript
         // Memo boundary: default shallow comparison on { buildingPk } string.
         // Parent re-renders (e.g. ConfigPanel header badge updating, language toggle
         // bubbling through Tabs) cannot force this chart to re-render unless buildingPk
         // actually changes. Combined with useEnergyBreakdown's referential stability
         // guarantee, this makes SC4 (no re-render during camera rotation) deterministic.
         export const EnergyBreakdownChart = memo(EnergyBreakdownChartImpl);
         EnergyBreakdownChart.displayName = "EnergyBreakdownChart";
         ```

    The displayName is important for the Profiler verification in Task 2 — without it, memo-wrapped components show up as `Memo(Anonymous)` in DevTools and the checkpoint-human cannot filter commits by name.

    Do NOT:
      - Write a custom `areEqual` comparator — default shallow comparison on a string prop is correct and cheaper.
      - Apply React.memo inside useMemo or inside a component body (memo must wrap at module level).
      - Memo any child elements inside the chart (the useMemo on chartData is already sufficient for internal stability).

    After editing, run `pnpm build` + `pnpm lint`. The import in config-panel.tsx does not change — `EnergyBreakdownChart` is still a named export.
  </action>
  <verify>
    <automated>pnpm build &amp;&amp; pnpm lint</automated>

  </verify>
